# Config contracts

A local agent overlay replaces the project entry's scalar fields, even when the local entry only adds permissions. Permission sets compose separately, so an omitted local set preserves the project set. Repeat any project scalar that the local entry must retain.

Target configuration controls both materialization and harness permission. Known harness targets grant permission; generic targets and paths do not. An explicitly supplied empty scope denies all harnesses, while absent targets are unrestricted. Provenance records the winning field and file even when two layers have equal values.

Use the shared routing-settings conversion so models commands and build policy interpret harness names and diagnostics identically.

The user folder is one folder on every platform (`platform/home.rs`): `MARS_HOME`, else `<home>/.mars` (Jimmy's call: each harness keeps one folder in home, and Mars does the same). It holds the user level's manifest, lock, `.mars-src`, store, and the user files `config.toml` and `curated.toml`. A relative `HOME` is ignored, because it would name a different folder from every working directory; a relative `MARS_HOME` resolves against the working directory, since the user typed it. With no absolute home and no variable set, there is no user config and no user level (`user-config-unlocated`, an `info`), and `--user` fails asking for `MARS_HOME`.

Two reads are kept for one minor release after 0.41.0 because 0.40 shipped them; after it, delete both. `MARS_CONFIG_DIR` is read as `MARS_HOME` when that is unset, with the `mars-config-dir-renamed` warning (also when both are set: the old one is ignored). `config.toml` and `curated.toml` at the 0.40 location (`dirs::config_dir()/mars`: `$XDG_CONFIG_HOME/mars` or `~/.config/mars` on Linux, `~/Library/Application Support/mars` on macOS) are read when the user folder has no copy, with the `user-config-moved` warning naming the move; when both exist the user folder's wins and the warning says the old one is ignored (`home::user_file`, `OldCopy`, `config::old_copy_warning`; `mars models list` prints the one for `curated.toml`). The old location is consulted only for the default folder: with a variable set it names the whole folder, and the fallback would otherwise read a developer's real files in a test that isolates with `MARS_HOME` (on Windows `dirs::config_dir` cannot be redirected by the environment).

The user level's manifest (`~/.mars/mars.toml`) is read and saved by the project code; its one rule is that `targets` and `managed_root` are errors in it and in its `mars.local.toml` (`refuse_user_targets`), since the user level has no targets and so never restricts routing. An absent user manifest loads as an empty `Config`, so nothing needs creating before `mars --user add`.
