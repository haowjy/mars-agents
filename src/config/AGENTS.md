# Config

Layers compose user, project, then local into `EffectiveConfig`. Consume that result rather than recomposing files, and never save it back to a source file: use the existing save path, which patches the authored TOML and verifies the result so unknown keys and comments survive.

`Config`, `Settings`, the overlays and `ModelAlias` are `mars_schema::config` and `mars_schema::alias`, re-exported here: the WASM `read('mars.toml')` shares them, so a new key or rule goes there (see that crate's `AGENTS.md`). Only what touches disk, the harness registry (`targets.rs`), the local and user files and layering stay here.

Model aliases and skill/agent overlays replace by key. An agent's network host sets compose across project and local layers; scalar fields in the local agent entry replace the project entry, and tool rule entries merge by key. Preserve absent versus explicitly empty.

`mars_schema::config::read_consumer` (for `mars.toml`, which also returns its refusals) and `read` (the local and user files) are the readers of all three files; this module loads the file, words its error as `failed to parse <path>: …` and adds the file name to the notes (`project_config_diagnostics`). Serde reads the keys Mars knows; every key it leaves unread becomes one `Info` (`field.unknown`) that names file, table and key, and stays in the file. Nothing here names a key, except `managed_root`, the one deprecated key: it is a layered setting like any other, and `effective_links` reads it as `targets` only when no layer sets `targets` (so a lower `targets` beats a higher `managed_root`, as in 0.36.1); each file warns `field.deprecated` through `mars_schema::config::managed_root_note`. Every writer of a file's `targets` (`link`, `unlink`, `init`) calls `targets::retire_managed_root` on that file first, so a saved file never keeps a key that a reload would layer back; delete the key, `retire_managed_root`, its fallback in `effective_links`, its two fields and its docs section in the minor after 0.37.0. Otherwise a key Mars once read and deleted is an unread key like a typo, and a bad value of a key Mars reads fails the load at its line (the whole-file error, `ConsumerRead::parse_error`: the schema also reads each table alone for the WASM, and the CLI refuses the project's own file whole). Don't add a per-key check or advice, a `flatten` map for unknown keys (it loses the line of a bad value) or a second parse path: a new key is a struct field, and a file Mars reads goes through `parse_config` or `parse_local` so `save` and `save_local` refuse what a load would. The underscore spellings `network_allow`, `network_deny`, `model_invocable` and `user_invocable` are serde aliases: 0.30.1 read them, and an ignored `network_deny` would drop a restriction without a line. The user config does not read `targets` or `[overrides]`; `user.rs` clears them and reports each as unread. `min_mars_version` parses as `requires-mars` does (`mars_schema::config::parse_min_mars_version`) and a value that does not fails the load of its file. A file's version floor comes from the key table (`mars_schema::keys::floor`, over `keys::used`), is set when the file is read, and `floor_warning` warns when the file does not state it, only above the first Mars that reads `min_mars_version`; it never writes the file. The floor stays a `Warning` because ignoring it costs a teammate's older Mars a dropped restriction. Plugin-only metadata stays raw at load so invalid publication metadata can't block sync; plugin build validation checks it.

Only known harness targets grant routing permission. Generic targets and paths materialize content without granting harness access; an explicitly empty scope must not become unrestricted. See [config contracts](.context/CONTEXT.md).
