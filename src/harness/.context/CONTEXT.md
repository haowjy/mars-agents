# Harness runtime descriptors

`mars-schema` owns harness identity; the runtime registry is the one row per harness (its class: native provider and auth-status command, or probe spec), and owns provider affinity and candidate order. `mars-schema` holds the host row (display name, tool table, MCP naming, effort levels). Facts derivable from `HarnessId` are not stored: the executable is `id.as_str()`, the target directory is `.{id}` (`HarnessId::target_dir`), and the skill variant key is `id.as_str()`. Lowering policy is a table in `src/compiler`, so `src/harness` never depends on the compiler. Keep those authorities shared so callers do not disagree about valid harnesses or routing order.

A capability session retains the probe outcome and its observation together. Re-reading the cache while formatting the same command could pair a decision with a different refresh's timestamp or error. Windows `.cmd` and `.bat` executable lookup belongs to the platform resolver; do not duplicate its suffix handling.
