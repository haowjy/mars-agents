# Provided skills, hooks and MCP servers

A host can install its own skills into `.mars/skills/` without adding dependencies or changing the package lock. It can also provide hooks and MCP servers, which `provide` validates with the readers sync uses and stages whole at `.mars/provided/<provider>/`.

**One owner per path.** `provide` is the only writer of `.mars/skills/<name>__<provider>`; sync never writes, replaces or removes it. Sync projects it into the targets that take provided content (`takes_provided`: a harness Meridian does not launch, `.agy` today) and records only those target outputs, in `.mars/machine.lock` (`lock/machine.rs` `split` is the one place that decides which records go there). Hooks and MCP servers are different: nothing launched reads them, so sync owns them whole. When a staged directory exists and a managed target takes provided content, `sync::load_config` adds it as the path dependency `_provided-<provider>` (the prefix is reserved in config), and every later step is the ordinary dependency path with three rules: the node's content is offered only to targets that take it (`provided::offered_to`); a package's item of the same key beats a provided one (`provided::yielded`, the one rule for hooks and MCP servers in `sync::target`'s single yield pass and for skills in `skill_outcomes`), and the hook or MCP server warns once, news when the host's bundle record or the package's changes; and a hook schema this Mars retired is kept as installed with a warning instead of halting, because the user cannot upgrade or remove a host.

Config entries a host's hooks and MCP servers wrote cannot be told from a package's by the record itself, so `sync::finalize` marks them from the selection and hands the set to `lock::build`, which cannot build a lock without it (`LockFile::provided_entries`); an entry no selection names keeps the file it was in. The lock's `_provided-<provider>` dependency carries the digest of the host's staged hooks and MCP servers (its `version` field, computed from `.mars/provided/<provider>/` by `ProvidedNames::load` and set by `lock::build`), so a sync can tell the host arrived or changed those, and a host upgrade that changes none is silent. `provide` digests the bundle's hooks and MCP servers without copying them and stages and parses only when something changed. Sync recognizes provided ownership so a package can replace a provided skill; reference validation separately checks whether a declared provided skill is available on disk.

The unlocked fast path and the locked pass use the same reconciliation plan. It checks every source skill and hashes installed trees: a package sync may have replaced a recorded directory before publishing its lock, and a formerly blocked skill may now be installable. Files are compared as authored, including executable bits.

The provider record authorizes removal or replacement of its own names; an unrecorded different directory is preserved. A package lock claim takes precedence. Before installation, the provider writes a pending record containing old and planned names, then installs and writes the final record. A crash leaves enough ownership information for the next run to reconcile, including removal of a skill the host has since dropped.

Provider names in the record must belong to that provider and be single path components: the record can have been written by another Mars build and must not authorize removal of another provider's files. Readers ignore an unsupported record version; the writer refuses it to avoid overwriting a newer format.
