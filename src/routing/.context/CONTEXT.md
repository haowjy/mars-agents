# Routing contracts

Fixed harnesses are assessed without fallback; profile and alias harnesses are preferences in the ordered candidate loop. Target permission applies to both. Generic targets and an explicitly empty scope grant no harness permission; only absent target configuration is unrestricted.

Selection kind says how a route was chosen; match evidence says what supports it. Keep those dimensions separate so a fixed choice does not imply confirmed support. Acceptance rejects blocked candidates even if their executable and model are present.

Support and authentication are independent: a successful gated Pi or Cursor listing implies configured authentication, but a failed latest listing does not, even when last-good model evidence remains. OpenCode's ungated listing does not establish authentication. Native compilation deliberately uses unchecked authentication so it can materialize supported agents without probing accounts.

Serialize `RouteDecisionReport`, not the internal trace: the report is the stable output boundary. Its selected pointer identifies an accepted route, including an earlier deferred attempt; it does not establish that a process ran.
