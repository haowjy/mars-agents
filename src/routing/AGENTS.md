# Routing

Models commands and launch bundles share candidate evaluation so they agree on harness selection. Apply configured target scope and caller exclusions before probing; preserve physical installation facts separately from permission.

Support, authentication and selection are separate facts. A supported authored preference can win before other eligible routes, except for passthrough or a failed latest gated listing. Otherwise defer the first unverified route while looking for an eligible one; never promote a blocked route. Authentication uncertainty is not rejection, and a successful credential-gated listing does not prove quota.

Native compilation assesses support without probing accounts. Runtime consumers use the selected assessment for availability and the launch ID rather than repeating support selection. See [routing contracts](.context/CONTEXT.md).
