# Sync

Sync resolves the complete desired package graph before compiling or changing installed content. Recovery commands may persist the user's config intent and stop before compilation when a hook uses an unreadable schema: the compiler must never receive a partial graph, or pruning and ownership become unsafe. Repair leaves a corrupt lock untouched until a complete sync can replace it.

New canonical outputs are journaled before they are written. Recovery checks the journal against the prior lock and the filesystem and fails closed on changed content or unsafe paths. `recovery::publish` publishes ownership (`mars.lock`, then the best-effort `.mars/native-agents.json` projection of it; a failed projection is only a warning) before removing the journal. Every command that writes `mars.lock` (`sync`, `link`, `unlink`, `resolve`) recovers the journal when it loads the lock and publishes through `publish`; one that doesn't wedges every later sync. Native and config outputs aren't journaled, nor is `--force` adoption of existing outputs: after a failed apply it needs `--force` again. See [recovery.rs](recovery.rs).

Dry runs must not create project state: they use scratch staging and acquire an existing sync lock without creating one. Every new write phase must honor dry-run mode.

Content from outside the project's own packages comes from the layers of `layer.rs`, the one table of them: the user level and a host. `layers::load` (called by `load_config`, after the lock is read) adds them as ordinary dependencies named with the layer's prefix: `_user-<name>`, pinned to the user `mars.lock` through `ResolveOptions::with_user_layer`, which sets `Dependency::namespace` on each root it injects (the core prefixes that root's own dependencies with it and replays them as `--frozen`; the namespace comes only from injection, and `Entry::read` refuses a reserved prefix in any manifest), `_user-self` for the user `.mars-src`, and `_provided-<host>` for a host's bundle (`--provided-root`, else the bundle the lock row records, else `mars provide`'s staging). Nothing after that knows a layer except through the table: `layer::yielded` (one pass in `sync::target`, items keyed by their name before collision renames) drops a worse layer's item a better layer claims, `layer::offered_to` limits a host to the targets that take it, and the lock writes every layer's records to `.mars/machine.lock`. Don't add a second way in. A package may replace a provided canonical item: provider ownership is recognized alongside lock ownership; `mars provide`'s skills still enter as outcomes from `provided::skill_outcomes` for one minor. See [provided](../provided/.context/CONTEXT.md). See [ownership.rs](ownership.rs) and [validate.rs](validate.rs).

Every output written for this machine only (a layer's content, a local-only target) gets exactly one decision in `machine_local.rs`: yield (the project's names and paths are rank-1 claims, read by the yield pass through `ProjectClaims`), withhold (a config entry in a file that can be committed) or install and exclude. Don't decide tracked, foreign or excluded anywhere else. What it leaves out is recorded as `LockFile::yielded` in `machine.lock` and warned once through `machine_local::leave_out`, so a removed record is still news. In a git work tree the exclusions go in this work tree's own block of the common dir's `info/exclude` (`exclude.rs`): from the decision before `apply_plan` writes anything, then exactly from the lock in `recovery::publish`, so every writer of the lock keeps it current. Git reads that file for every work tree, so another work tree's block can hide this project's path; the sync warns once (a note line in the block) and cannot do better without writing a `.gitignore`, which it must not.

Sync plans, writes and removes only the records of the targets it manages. `load_config` splits the lock (`LockFile::split_targets`) twice: the pipeline holds only the managed targets' records in the lock it reads and the lock it builds; `carried` holds the records of a target a config file names but the sync does not manage (retired `.cursor`; `mars.local.toml`'s `targets` adds to the project's, so no other named target is unmanaged), which `finalize` joins back (`LockFile::join`) after `settle`; `dropped` holds the records of a target no config file names, which `finalize` removes through `target_sync::removal::remove_served`, the code `mars unlink` runs, before the lock is published. That code deletes an output only while it is still what Mars wrote (`installed_checksum`); an edited one stays and is reported (`target_sync/.context/CONTEXT.md`). Compare and prune only through that split: a record the pipeline never holds can't be taken for news or deleted. Don't add a second path for a target Mars stopped writing: it is this one. `--frozen` refuses a sync that would remove a dropped target.

Sync and plugin builds share target selection and renaming. Sync removes unmanaged collisions before rewriting references. Hook and MCP entries are lowered from the selected target state, never rediscovered, and their config must not reference a directory target sync failed to install. Invalid dependency hooks can retain the directories and outputs recorded in the lock rather than being pruned as removed.

See [target sync ownership](../target_sync/.context/CONTEXT.md) and [resolution](../resolve/AGENTS.md).

`lock::write` files each record in `mars.lock` or `.mars/machine.lock` by the targets `mars.toml` names, so `finalize` and every other `publish` caller passes `project_targets(&config)`; a writer that passes something else moves records between files. See [lock contracts](../lock/.context/CONTEXT.md).
