# Targets

Hook placement and rendering belong to `mars-schema::hooks`, not the target row's MCP specification. Hook entries are unkeyed array elements, so their removal and rewrite use the shared retention plan, not MCP's keyed reconciliation.

Keyed entries share one engine, `keyed_entries.rs`: MCP servers, and for a plugin target (`.agy`) its pointer in `.agents/plugins.json`, its `plugin.json` keys and its hooks. A user of it declares a `KeyedSection` (file and section shape) and a `KeyedKind` (lock key prefix, message nouns, diagnostic code prefix) and lists them from `TargetSpec::keyed_sections`; sync and unlink both reconcile through it, so a new kind is a declaration, not a second engine. Its diagnostic codes and texts are user-visible. A section shape (`SectionFormat`) is a `Doc` accessor set in `config_doc.rs`: `JsonSection`, `TomlTable`, `JsonTopLevel` and `JsonArrayByField`.

A target is one row of `table.rs` (`TargetSpec`: MCP file and render function, plugin files, whether the harness reads `.agents/skills/`, and how `${MARS_MCP_DIR}` reaches `args`); `.agents` is the row with no harness, and a name with no row (`mars link foo`) is a plain copy target. A plugin target (`.agy`) is a row with `plugin` set: it declares where its pointer, manifest and hook file are, and `keyed_sections` and `fixed_entries` (what the target has whenever it is managed) follow from it. The hook file's section comes from the hook table (`mars-schema::hooks::targets`, `Placement::Keyed`), which alone names the file, so a target with keyed hooks needs no plugin field for it. A new keyed kind never needs a branch in `compiler/config_entries`: it needs a declaration and, if packages feed it, an entry in the compile loop.

A retired target has no adapter. Sync never reaches its records (`LockFile::split_targets`), so `keyed_sections` names the MCP file the retired table names only for `target_sync::removal` (`mars unlink`, and a sync once `targets` stops naming the target), which removes the recorded entries, and `compiler::config_entries::hook_file` does the same for its hook file.

Ownership applies to entries, not the containing file. Reconcile removes or replaces only recorded, unchanged entries; edited entries are kept unless forced, and failed writes retain previous records for retry. An empty config file is removed only when reconciliation changed it and left it empty: an untouched empty file may be the user's.

Config writes preserve existing permissions and write through symlinks so a user's link survives. Generated agent filenames are validated for Windows on every platform. Ordered JSON editing preserves the user's key order without enabling `serde_json/preserve_order` globally, which would change unrelated JSON output.
